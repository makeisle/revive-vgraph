# 상주 서버 모드 (`vgraph-mcp serve`)

여러 MCP 클라이언트(에이전트)가 **한 데이터 폴더를 함께** 쓰려면, 클라이언트마다 `vgraph-mcp`(stdio)를 따로 띄우는 대신
**서버 하나**를 띄우고 모두 그 서버에 HTTP로 접속합니다. 서버 안에는 엔진이 하나뿐이라, 같은 그래프·같은 브랜치를 동시에
편집해도 커밋된 편집이 사라지지 않습니다(동시 편집 보호는 엔진이 맡습니다).

- 하위 명령 없이 `vgraph-mcp`를 실행하는 기존 stdio 방식은 **그대로**입니다. 한 프로세스만 쓰는 사용 방식은 바뀌지 않았습니다.
- 이 문서의 명령·옵션 이름은 실제 `vgraph-mcp --help`(하위 명령 포함) 출력과 대조해 적었습니다.
- **같은 PC 밖에서 접속하게 열려면** [remote-access.md](remote-access.md)를 보십시오(TLS·사용자별 토큰·바인드 규칙·프록시 배치).

## 목차

1. 서버 띄우기·끄기·상태
2. 로그인할 때 자동으로 띄우기 (`service`)
3. MCP 클라이언트 연결 설정 예
4. 접속별 사용자·작업 공간
5. 토큰과 접속 범위
6. 주의·한계
7. 라이브러리로 쓸 때 서버 의존성 빼기
8. 그래프 이름 찾기·가져오기·브랜치 이름
9. 검색 옵션과 간결 출력
10. 큰 문서 나눠 내보내기·나눠 올리기

## 1. 서버 띄우기·끄기·상태

```text
vgraph-mcp serve --root <데이터 폴더>
vgraph-mcp status --root <데이터 폴더>
vgraph-mcp stop   --root <데이터 폴더>
```

| 명령 | 하는 일 |
|---|---|
| `serve` | 상주 HTTP 서버를 띄웁니다. 터미널을 잡고 있으며, 서버가 준비되면 실제 주소를 출력합니다. |
| `status` | 그 데이터 폴더에서 떠 있는 서버의 주소·PID를 보입니다. 떠 있으면 종료 코드 0, 아니면 1입니다. |
| `stop` | 서버를 끕니다. 정상 종료를 먼저 요청하고, 10초 안에 끝나지 않으면 강제 종료합니다. |

- **기본 주소:** `127.0.0.1:7437`, 접속 경로는 `/mcp`입니다(`http://127.0.0.1:7437/mcp`).
- **`--listen <주소>`:** 다른 주소로 열 때 씁니다. **루프백이 아닌 주소(사설·공인·`0.0.0.0` 등)는 TLS와 사용자별 토큰을 모두 줘야만
  뜹니다**(하나라도 없으면 이유를 알리고 뜨지 않습니다). 규칙 전체는 [remote-access.md](remote-access.md) 1절입니다.
  포트를 `0`으로 주면 운영체제가 빈 포트를 골라 주고, 실제 주소를 출력합니다.
- **`--root`:** 데이터 폴더(기본 `./vgraph-data`). `status`·`stop`에는 `serve`에 준 것과 같은 값을 줍니다.
- 그 밖에 `--user`, `--embedder`, `--embed-fields`, `--chunker`, `--no-embed-fallback`은 stdio와 같은 뜻입니다.
  (`--workspace`는 서버 모드에 없습니다. 작업 공간은 접속별 헤더로 정합니다 — 4절.)
- **원격·인증 옵션:** `--tokens <파일>`(사용자별 토큰), `--tls-cert <PEM>`·`--tls-key <PEM>`(HTTPS), `--behind-proxy`(리버스 프록시 뒤,
  평문), `--allow-origin <출처>`(브라우저 출처 허용, 여러 번 가능). 모두 선택이며 주지 않으면 지금까지와 같게 동작합니다. 자세한 내용은
  [remote-access.md](remote-access.md)입니다. 사용자별 토큰은 `vgraph-mcp token add|list|revoke`로 관리합니다(5절).
- **`--detach`:** 콘솔에 붙지 않는 자식 프로세스로 서버를 다시 띄우고 명령은 곧바로 끝납니다. 서버 출력은
  `--log-file`(기본 `<데이터 폴더>/server.log`)에 남습니다.

### 중복 기동 차단

같은 데이터 폴더에는 서버를 **하나만** 띄울 수 있습니다. 두 번째 `serve`는 "이 데이터 폴더에는 이미 서버가 떠 있습니다
(주소 …, PID …)"를 출력하고 종료 코드 1로 끝납니다. 첫 서버는 영향을 받지 않습니다. 데이터 폴더가 다르면 서버를 여러 개
나란히 띄울 수 있습니다.

### 데이터 폴더에 생기는 파일

서버 모드에서만 생기며, stdio로 실행하면 만들지 않습니다.

| 파일 | 내용 |
|---|---|
| `server.lock` | 빈 파일. 운영체제 파일 잠금으로 중복 기동을 막는 데 씁니다. |
| `server.info` | 서버의 PID·주소·버전(JSON). 토큰 값은 들어가지 않습니다. |
| `server.stop` | `stop`이 서버에 종료를 알리는 신호 파일. 서버가 확인하면 지웁니다. |
| `server.log` | `--detach`(또는 `service`로 등록한 서버)의 출력 로그. |

`stop`으로 끈 뒤에도 **빈 `server.lock`이 남는 것은 정상**입니다(잠금이 풀린 빈 파일일 뿐입니다). 지워도 되고 두어도 됩니다.

## 2. 로그인할 때 자동으로 띄우기 (`service`)

```text
vgraph-mcp service install  --root <데이터 폴더> [serve 인자…]
vgraph-mcp service status
vgraph-mcp service uninstall
```

현재 사용자가 로그인할 때 서버가 자동으로 뜨도록 등록합니다. **관리자 권한은 필요 없습니다.** 등록은 사용자당 하나입니다.

| 운영체제 | 등록 위치 | 검증 상태 |
|---|---|---|
| Windows | 현재 사용자 시작 항목(`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`). `serve --detach`로 창 없이 뜹니다. | **실기 확인함** (등록·창 없는 기동·상태·해제) |
| macOS | `~/Library/LaunchAgents`의 LaunchAgent(`launchctl`) | **실기 미검증** — 생성되는 등록 내용만 시험으로 고정했습니다 |
| Linux | `~/.config/systemd/user`의 사용자 단위(`systemctl --user`) | **실기 미검증** — 생성되는 등록 내용만 시험으로 고정했습니다 |

- `install`은 등록하고 **지금 바로 서버도 띄웁니다.** 이미 등록돼 있으면 덮어쓰며, 그 서버가 떠 있으면 먼저 끕니다.
- `install` 옵션: `serve`와 같은 인자에 더해
  - `--no-start` — 등록만 하고 지금은 띄우지 않습니다.
  - `--log-file <파일>` — 서버 출력 로그 위치(기본 `<데이터 폴더>/server.log`).
  - `--print <windows|macos|linux>` — 등록하지 않고 그 운영체제용 등록 내용만 출력합니다(등록 전에 내용을 확인할 때 씁니다).
- `--root`·`--token-file`·`--log-file`은 **절대 경로로 바뀌어** 등록됩니다. 실행 파일은 지금 실행 중인 `vgraph-mcp`이므로,
  파일을 옮기면 `install`을 다시 하십시오.
- `uninstall`은 서버를 끄고 등록을 지웁니다(등록이 없으면 아무것도 하지 않습니다).
- `service status`는 등록돼 있고 서버가 떠 있을 때만 종료 코드 0, 아니면 1입니다.
- **토큰은 등록 항목에 평문으로 넣지 않습니다.** `--token-file`의 경로만 들어가며, `install`에 `--token`을 주면 거부합니다.

**미확인:** 로그인할 때 실제로 자동으로 뜨는지(로그아웃·재로그인이 필요해 확인하지 못했습니다)와, Windows에서 로그인 시 콘솔
창이 잠깐 깜빡일 수 있는지는 **확인하지 못했습니다.** 등록된 명령을 직접 실행했을 때 창 없이 뜨는 것까지만 확인했습니다.

## 3. MCP 클라이언트 연결 설정 예

서버는 MCP의 HTTP 방식(Streamable HTTP)으로 `http://127.0.0.1:7437/mcp`에 접속을 받습니다. 클라이언트 설정에는
접속 주소(`url`)와, 필요하면 신원·토큰 헤더(`headers`)를 넣습니다.

**JSON 설정 예** (HTTP 방식을 지원하는 MCP 클라이언트의 설정 파일 형태. 키 이름은 클라이언트마다 다를 수 있으니 해당
클라이언트 문서에 맞추십시오):

```json
{
  "mcpServers": {
    "vgraph": {
      "type": "http",
      "url": "http://127.0.0.1:7437/mcp",
      "headers": {
        "X-Vgraph-User": "alice",
        "X-Vgraph-Workspace": "my-agent"
      }
    }
  }
}
```

**명령줄 예** (예: Claude Code. `vgraph-mcp serve --help`에도 같은 예가 있습니다):

```text
claude mcp add --transport http vgraph http://127.0.0.1:7437/mcp --header "X-Vgraph-Workspace: my-agent"
```

이 명령줄 예를 실제 클라이언트로 접속해 확인하는 일은 이 문서의 검증 범위 밖입니다(별도 확인 대상). 서버 쪽 HTTP 동작은
시험으로 확인했습니다.

토큰을 쓰는 서버라면 `headers`에 `"Authorization": "Bearer <토큰>"`을 함께 넣습니다(5절).

## 4. 접속별 사용자·작업 공간

접속(MCP 세션)마다 요청 헤더로 신원을 정합니다.

| 헤더 | 뜻 | 생략하면 |
|---|---|---|
| `X-Vgraph-User` | 사용자(ACL 소유자). **`--tokens` 서버에서는 무시되고 토큰이 사용자를 정합니다** | 서버를 띄울 때 준 `--user`(기본 `local`) |
| `X-Vgraph-Workspace` | 작업 공간 이름(영문·숫자·`-`·`_`) | 서버가 **MCP 세션마다 새 작업 공간**(`s-<ULID>`)을 붙입니다 |

- 작업 공간이 서로 다르면 같은 사용자·같은 그래프·같은 브랜치를 동시에 편집해도, 커밋할 때 자동으로 합쳐집니다. 같은 값을 서로
  다르게 바꿨으면 유실하지 않고 **충돌로 보고**됩니다.
- 같은 이름으로 다시 접속하면 그 작업 공간을 이어 씁니다(커밋하지 않은 편집도 이어집니다).
- 잘못된 작업 공간 이름은 JSON-RPC 오류(-32600)로 거절됩니다.
- 헤더 없는 접속끼리는 서로의 커밋하지 않은 편집이 보이지 않습니다. 같은 세션 안에서는 요청이 여러 번이어도 같은 작업 공간입니다.

## 5. 토큰과 접속 범위

- **기본은 루프백 한정:** `--listen`을 주지 않으면 서버는 `127.0.0.1` 같은 루프백 주소로만 열립니다. 루프백 서버는 루프백이 아닌
  `Origin` 헤더가 붙은 요청을 403으로 거절합니다(브라우저 페이지가 몰래 접속하는 것을 막기 위한 장치). 밖으로 열려면
  [remote-access.md](remote-access.md)의 절차(TLS + 사용자별 토큰)를 따라야 하며, 이때는 `--allow-origin`에 적은 출처만 받습니다.
- **토큰(선택, 모두가 함께 쓰는 하나):** 토큰을 주면 `Authorization: Bearer <토큰>`이 맞는 접속만 받고, 아니면 401을 돌려줍니다.
  - **`--token-file <파일>`을 권장합니다.** 파일의 앞뒤 공백·줄바꿈은 무시합니다.
  - `--token <값>`도 되지만 명령줄 인자는 프로세스 목록에 보입니다. `--token`과 `--token-file`은 함께 쓸 수 없습니다.
  - `service install`은 `--token`을 거부하고 `--token-file`만 받습니다(등록 항목에 토큰 값이 남지 않게).
  - 토큰 값은 서버의 출력·오류 메시지·`server.info`에 나타나지 않습니다.
  - 이 공유 토큰은 **같은 PC 밖으로 여는 서버의 인증으로는 인정되지 않습니다**(누가 접속했는지 알 수 없어서).
- **사용자별 토큰(`--tokens`):** 사용자마다 `vgraph-mcp token add <사용자>`로 따로 발급합니다. 토큰 원문은 발급할 때 **한 번만** 보이고 파일에는
  해시만 저장됩니다. 서버에 `--tokens <파일>`을 주면 `Authorization: Bearer <토큰>`이 맞는 접속만 받고, **토큰이 사용자를 정합니다**
  (`X-Vgraph-User` 무시). `token revoke <id>`는 실행 중인 서버에 곧바로 반영됩니다. `--tokens`는 `--token`·`--token-file`과 함께 쓸 수
  없고, 주지 않으면 지금까지와 같습니다. 발급·전달·폐기 절차는 [remote-access.md](remote-access.md) 3절입니다.
- 토큰이 없어도(밖으로 열지 않은 서버라면) 루프백 한정은 유지됩니다. 같은 PC의 다른 사용자 계정이 접속할 수 있다는 점은 감안하십시오(필요하면 토큰을 쓰십시오).

## 6. 주의·한계

- **stdio 방식과 서버를 같은 데이터 폴더에 섞어 쓰지 마십시오.** 서버 안의 엔진과 stdio로 띄운 `vgraph-mcp`의 엔진이 **둘이 되어**
  동시 편집 보호가 약해집니다. 같은 사용자·같은 브랜치·같은 작업 공간이면 편집이 사라질 수 있습니다(v0.2.0의 `--workspace`
  안내와 같은 취지입니다). 서버를 쓰기로 했으면 그 폴더에 접속하는 모든 클라이언트를 서버로 모으십시오. stdio 쪽에는 서버가
  떠 있는지 확인하는 검사나 경고를 넣지 않았습니다(기존 동작 불변).
- **자동 작업 공간은 재접속하면 바뀝니다.** 이어서 편집하려면 `X-Vgraph-Workspace` 헤더로 이름을 고정하십시오.
- **커밋하지 않고 끊은 자동 작업 공간의 편집은 데이터 폴더에 남아 쌓입니다.** 자동 정리는 아직 없습니다(후속 과제). 헤더 없이
  짧게 접속하는 클라이언트가 많은 환경에서는 이 점을 감안하십시오.
- **세션은 클라이언트가 종료 요청(HTTP `DELETE`)을 보내야 닫히고, 만료가 없습니다.** 열 수 있는 세션은 최대 4096개이며, 넘으면
  새 `initialize`가 503으로 거절됩니다. 서버를 다시 띄우면 세션은 모두 사라집니다.
- 유실 방지 시험: 한 서버에 클라이언트 5개(헤더 없는 3개 + 작업 공간 이름 지정 2개)가 같은 그래프·같은 브랜치를 동시에
  편집·커밋하는 시험을 50회 반복해 유실 0, 엔진 프로세스 1개를 확인했습니다
  (`cargo test -p vgraph-mcp --test http_concurrency -- --ignored --nocapture`, 수동 실행).
- Windows 이외(macOS·Linux)의 `service` 등록은 **실기 미검증**입니다(2절).
- **밖으로 여는 서버의 한계**(동시 연결 수 상한 없음, 공개 인터넷 운영은 범위 밖 등)는 [remote-access.md](remote-access.md) 10절입니다.
- 원격 동시 편집 시험(서로 다른 토큰의 클라이언트 5개, TLS)은 `cargo test -p vgraph-mcp --test remote_concurrency -- --ignored --nocapture`
  (수동 실행, 이 PC 밖으로 열리는 주소에 바인드하므로 방화벽 창이 뜰 수 있음)입니다.

## 7. 라이브러리로 쓸 때 서버 의존성 빼기

`vgraph-mcp`는 기능 `server`(기본 켬)에 서버 모드(HTTP 서버·파일 잠금 등)를 담고 있습니다. 라이브러리로 가져다 쓰면서 서버가
필요 없다면 기본 기능을 꺼서 서버 계열 의존성이 들어오지 않게 하십시오.

```toml
[dependencies]
vgraph-mcp = { path = "../revive-vgraph/crates/vgraph-mcp", default-features = false }
```

`default-features = false`로 빌드하면 서버 모드(`serve`·`stop`·`status`·`service`)가 빠지고 stdio 서버만 남습니다. 이 빌드의 실행
파일 도움말에는 "이 빌드에는 상주 서버 기능이 없다"고 표시됩니다.

## 8. 그래프 이름 찾기·가져오기·브랜치 이름

아래 동작은 상주 서버뿐 아니라 stdio 방식에도 같은 도구로 적용됩니다. 옵션을 주지 않은 기존 호출의 응답 형식은 바뀌지 않았습니다.

**다른 프로세스가 만든 그래프 인식 (레지스트리 다시 읽기)**
- 떠 있는 서버(또는 엔진)가 모르는 그래프 이름을 만나면 그때 `registry.jsonl`을 다시 읽어, 다른 프로세스(예: 별도 `vgraph-mcp`
  stdio 프로세스)가 새로 만든 그래프를 찾습니다. 이미 아는 이름은 파일을 다시 읽지 않습니다. `vgraph_list`도 새 그래프를 보여 줍니다.
- 그래프를 만들 때는 데이터 폴더의 `registry.lock`(만드는 순간에만 잠깐 생김)으로 묶은 구간에서 이름을 다시 확인합니다. 다른
  프로세스가 먼저 만든 이름은 "이미 있음(`graph exists`)"으로 거부하고, 동시에 같은 이름을 만들어도 하나만 성공합니다. 잠금을
  5초 안에 얻지 못하면 `registry lock busy: <경로>` 오류가 나며, 10초 넘게 남은 잠금은 비정상 종료 흔적으로 보고 치웁니다.
- 이것이 **동시 편집 보호를 되살리는 것은 아닙니다.** stdio와 서버를 같은 데이터 폴더에 섞어 쓰지 말라는 6절의 주의는 그대로입니다.

**이름 모호 오류**
- `registry.jsonl`에 **같은 이름이 둘 이상** 들어 있으면 데이터를 임의로 고르지 않고 "graph name … is ambiguous" 오류로 알립니다
  (`vgraph_list`에는 둘 다 보입니다). 불필요한 줄을 `registry.jsonl`에서 지우면 해소됩니다. 이 오류는 주소 오류(`bad address`)와
  구별되는 별도 종류입니다.

**가져오기: 모르는 칸 거부**
- `vgraph_import` 문서의 최상위(`format`·`nodes`·`edges`), `nodes[i]`(`slug`·`labels`·`props`), `edges[i]`(`etype`·`from`·`to`·`props`)에
  형식이 정의하지 않은 칸이 있으면 **아무것도 넣지 않고 전체를 거부**하며, 위치를 모두 알립니다. 예: `모르는 칸 1 건 … nodes[3].label`
  (`labels`를 `label`로 쓴 경우). `replace`·`merge`·나눠 올리기 모두 같습니다. `props` 안의 키는 사용자 데이터라 검사하지 않습니다.
- JSON 형식 오류·slug 누락 같은 오류가 먼저 있으면 그 오류가 먼저 나오고, 모르는 칸은 그것을 고친 뒤 드러납니다.
- 이전에는 모르는 칸을 조용히 무시했으므로, 형식에 없는 칸을 붙여 쓰던 문서는 이제 거부됩니다(의도된 변경).

**브랜치 이름 규칙 (`/` 허용)**
- 브랜치 이름은 **영문·숫자·`-`·`_`·`/`** 만 쓸 수 있습니다(`feature/x` 같은 계층형 이름). 빈 이름, 앞뒤의 `/`, 연속 `//`, 그리고
  `.`·`@`·`#`·공백 등은 만들 때 거부됩니다. 길이 상한은 없습니다.
- 주소에서는 `ns/slug@feature/x`처럼 씁니다(`@` 뒤가 브랜치). 브랜치 만들기·주소 해석·가져오기 `via_branch`가 **같은 규칙**을 씁니다.
  그래프 `ns`·`slug`에는 `/`를 쓸 수 없는 규칙이 그대로입니다.
- 규칙은 **새로 만들 때만** 적용됩니다. 옛 규칙 밖의 이름으로 이미 있는 브랜치는 `vgraph_log`·`vgraph_merge`에서 계속 쓸 수 있습니다.
- 작업 공간 이름(`X-Vgraph-Workspace`)의 규칙(영문·숫자·`-`·`_`)은 별개이며 바뀌지 않았습니다.

## 9. 검색 옵션과 간결 출력

모두 **선택 인자**입니다. 주지 않으면 기존 응답과 바이트 단위로 같습니다.

**`vgraph_find`**

| 인자 | 하는 일 |
|---|---|
| `order:"relevance"` | 관련도 높은 순으로 상위 `limit`개를 돌려줍니다. 점수는 일치 강도(값 전체 3 · 앞부분 2 · 부분 1)×10 + 출처(slug 2 · 라벨 1 · 속성 0), 동점이면 uuid 순입니다. 응답에 `order`·`total_matches`와 항목별 `score`가 붙습니다. `cursor`와는 함께 쓸 수 없습니다(거부). 후보는 **속성에서 맞은 노드**로 한정되고, slug·라벨은 점수만 올립니다. |
| `normalize:true` | 공백류·밑줄·붙임표류(`-`, U+2010~2015, U+2212, U+FE63, U+FF0D)를 무시하고 비교합니다. 발췌는 원문 기준입니다. 구분 문자뿐인 `text`(예: `"-"`)는 빈 표현으로 버려져 조건 없음과 같습니다. |
| `any:[…]` | `text`(있으면 첫째)와 `any`의 표현들을 OR로 찾습니다. `any`를 줬을 때만 항목에 `matched_expr`가 붙습니다. |
| `skip_ref_like:true` | 공백 없이 `graph://ns/slug[@branch][.commit][#node]` 문법에 맞는 문자열 값(목록이면 원소별)을 텍스트 검색에서 뺍니다. 문장 속 주소, 축약형(`ns/slug#node`), 문법에 맞지 않는 값은 일반 텍스트로 검색합니다. |

- `order:"relevance"`는 후보를 모두 평가·정렬하므로 일반 `find`보다 느립니다(노드 3000개, release 기준 측정: 일반 약 0.05~0.07ms, relevance 약
  20ms, relevance+normalize+any 약 88ms. 노드 수가 훨씬 많을 때는 측정하지 않았습니다).

**`compact:true`** — `vgraph_find`·`vgraph_neighbors`·`vgraph_scan`·`vgraph_search`에서 응답의 고정 칸을 뺍니다(측정한 질의에서 대략 1.4~2.9배 작아짐).
- 최상위 `epoch`를 뺍니다(`cursor`는 유지되어 이어 받기가 됩니다).
- 노드는 slug가 있으면 `slug`만, 없으면 `uuid`만 냅니다. `neighbors`는 `via`(엣지 uuid)를 빼고, `scan`의 엣지는 엣지 `uuid`를 빼며 양끝을
  `from_slug`/`to_slug`(slug가 없으면 `from`/`to`)로 냅니다.
- 같은 양끝·같은 종류의 병렬 엣지는 compact 응답만으로 구별되지 않고, 마지막 쪽에서는 `epoch`가 없어 버전을 알 수 없습니다. 필요하면 compact를
  끄고 부르십시오.

## 10. 큰 문서 나눠 내보내기·나눠 올리기

원격 접속에서는 서버 파일 경로(`path`)를 쓸 수 없는 경우가 많으므로, 문서를 응답·요청 본문으로 조각내 주고받는 방법을 더했습니다. `path`·`document`를 쓰는
기존 방식은 그대로입니다.

**나눠 내보내기 — `vgraph_export`**
- `max_bytes`(조각 하나의 최대 바이트, **1024~4194304**)를 주면 한 조각이 `{epoch, nodes, edges, chunk, offset, total_bytes, done, next_cursor}`로
  옵니다. `done:false`이면 `next_cursor`를 `cursor`로, **같은 `graph`·`max_bytes`와 함께** 다시 부릅니다(`cursor`를 쓸 때 `max_bytes`는 필수).
- 첫 호출 시점의 커밋에 고정되므로, 받는 동안 브랜치에 새 커밋이 생겨도 같은 판의 다음 조각이 옵니다. `done:true`가 올 때까지 `chunk`를
  순서대로 이어 붙이면 한 번에 내보낸 문서와 바이트 단위로 같습니다(조각은 문자 중간에서 자르지 않음). `path`와는 함께 쓸 수 없습니다.
- 권장 `max_bytes`: **64KB~1MB**(응답 안에서 JSON 이스케이프로 커질 수 있음). 서버는 커서를 상태로 보관하지 않고 조각마다 문서를 다시 만들기 때문에,
  아주 작은 조각으로 큰 그래프를 받으면 느립니다(약 3.8MB를 64KB 조각으로 받는 시험이 debug 빌드에서 약 22초).
- `cursor` 값은 불투명한 문자열이니 그대로 돌려주십시오.

**나눠 올리기 — `vgraph_import`의 `upload`**
1. `{"graph":"acme/catalog","upload":"begin"}` — `mode`·`via_branch`·`message`는 여기서만 주고, 그 자리에서 검증됩니다. 응답에 `upload_id`.
2. `{"graph":…,"upload":"append","upload_id":"…","seq":0,"chunk":"문서의 앞부분"}` — `seq`는 0부터 하나씩 늘립니다. 틀리면 기대 값을 알려 주며
   거부합니다. 응답은 `{received_bytes, next_seq}`.
3. `{"graph":…,"upload":"commit","upload_id":"…"}` — 모은 문서를 일반 가져오기와 같은 규칙(검증·모르는 칸 거부·가져오기 1회 = 커밋 1개)으로 넣고
   같은 응답을 줍니다. **확정이 거부돼도 업로드는 지워지니 처음부터 다시 올립니다.**
4. 그만두려면 `{"graph":"acme/catalog","upload":"abort","upload_id":"…"}`.

- `graph`는 매 호출에 주고 `begin`과 같아야 합니다. `document`·`path`와는 함께 쓸 수 없고, `upload` 없이 `upload_id`·`chunk`·`seq`만 주면 거부됩니다.
- **상한(기본):** 문서 **64MiB**, 동시 **8개**(서버 전체 공용), 마지막 사용 후 **10분** 지나면 만료. 넘으면 명확한 오류가 납니다.
- **권장 `chunk` 크기:** 64KB~1MB, 8MiB 이하. 상주 서버는 HTTP 요청 본문을 **16MiB**까지만 받으며(이스케이프 포함) 넘으면 413입니다. 8MiB는 코드 상한이 아닌
  안내 수치입니다.
- 업로드는 **서버 프로세스 메모리에만** 있습니다(재시작하면 사라지고 디스크에 남지 않음). 시작한 사용자·작업 공간만 이어 쓸 수 있고, 다른 쪽에는 "없는
  업로드이거나 만료"로 보입니다.
- `begin`은 그래프 권한을 미리 보지 않고 `commit`에서 거부합니다. 동시 업로드 8개를 한 신원이 다 쓰면 다른 사용자는 만료(10분)까지 새로 시작하지 못합니다.
