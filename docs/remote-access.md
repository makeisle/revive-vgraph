# 원격 공개 (같은 PC 밖에서 접속하기)

`vgraph-mcp serve`는 기본적으로 이 PC 안(루프백)에서만 접속을 받습니다. 같은 사무실 망이나 다른 PC의 에이전트가 접속해야 한다면
이 문서의 절차로 서버를 **밖으로 엽니다.** 밖으로 여는 서버는 아래 세 가지를 **모두** 갖추지 않으면 시작하지 않습니다.

1. **TLS(HTTPS)** — 인증서와 개인키 (`--tls-cert`, `--tls-key`)
2. **사용자별 토큰** — 사용자마다 따로 발급한 토큰 (`--tokens`)
3. (브라우저 앱이 접속할 때만) **허용 출처 목록** (`--allow-origin`)

- 한 프로세스만 쓰는 기존 사용 방식(stdio)과, 옵션 없이 띄우는 루프백 서버의 동작은 바뀌지 않았습니다.
- 이 문서의 옵션 이름과 기본값은 실제 `vgraph-mcp serve --help`·`token --help`·`service install --help` 출력과 대조해 적었습니다.
- 서버 모드 전반(기본 사용법·작업 공간·세션)은 [server-mode.md](server-mode.md)를 보십시오.

## 목차

1. 바인드 규칙 — 어떤 주소로 열 수 있나
2. 인증서와 개인키 준비
3. 토큰 발급·전달·폐기
4. 서버 띄우기 (`serve` 예시)
5. 리버스 프록시 뒤에 두기
6. 브라우저 앱을 위한 `--allow-origin`
7. 로그인할 때 자동으로 띄우기 (`service install`)
8. 방화벽
9. MCP 클라이언트 연결 예
10. 알려진 한계와 검증 상태

## 1. 바인드 규칙 — 어떤 주소로 열 수 있나

`--listen <주소:포트>`에 준 주소를 서버가 **바인드하기 전에** 검사합니다. 규칙을 어기면 이유를 알리고 종료 코드 1로 끝나며,
데이터 폴더도 만들지 않습니다.

| `--listen` 주소 종류 | 일반 모드 (기본) | 프록시 모드 (`--behind-proxy`) |
|---|---|---|
| **루프백** (`127.0.0.1`, `::1`) | 허용. TLS·토큰 없이도 됩니다(지금까지와 같음). | 허용 (평문). **`--tokens` 필수.** |
| **사설** (`10.x`, `172.16`~`172.31.x`, `192.168.x`, IPv6 `fc00::/7`) | **TLS + `--tokens` 둘 다 필수** | 허용 (평문). **`--tokens` 필수.** |
| **공인** (인터넷에서 닿는 주소) | **TLS + `--tokens` 둘 다 필수** | **거부** |
| **전체 주소** (`0.0.0.0`, `::`) | **TLS + `--tokens` 둘 다 필수** (밖으로 열리는 주소로 봅니다) | **거부** |

- 위 표의 "필수"가 하나라도 빠지면 시작하지 않고, 빠진 것을 알려 줍니다.
- **공유 토큰(`--token`, `--token-file`)은 원격 인증으로 인정되지 않습니다.** 공유 토큰은 접속하는 모두가 같은 값을 쓰는
  하나뿐이라, 누가 접속했는지 알 수 없고 한 사람만 빼기도 어렵습니다. 밖으로 여는 서버는 사용자별 토큰(`--tokens`)만
  받습니다. TLS를 줘도 `--token-file`만 있으면 거부하고 `--tokens`를 안내합니다.
- `--tokens`는 `--token`·`--token-file`과 함께 쓸 수 없습니다.
- 포트를 `0`으로 주면 운영체제가 빈 포트를 골라 주고 실제 주소를 출력합니다. 방화벽 규칙을 만들 때는 포트를 고정하십시오(8절).

## 2. 인증서와 개인키 준비

- 서버 인증서(`--tls-cert`)와 개인키(`--tls-key`)는 **PEM 파일**이어야 합니다. 둘은 함께 줘야 합니다.
- 개인키 형식은 **PKCS#8, PKCS#1, SEC1** 세 가지를 모두 읽습니다.
- 키 파일의 내용은 로그·`server.info`·`status`·오류 메시지 어디에도 출력하지 않습니다.
- 인증서의 주소(SAN)에는 **클라이언트가 접속할 주소(호스트 이름 또는 IP)** 가 들어 있어야 합니다. 맞지 않으면 클라이언트가
  인증서 오류로 접속을 거부합니다.
- **자체 서명 인증서는 시험용입니다.** 클라이언트가 그 인증서를 직접 신뢰하도록 설정해야 하고, 신뢰 설정 방법은 클라이언트마다
  다릅니다. 실제로 쓰는 서버는 조직의 인증 기관(또는 공개 인증 기관)이 발급한 인증서를 쓰십시오.
- 인증서 파일을 바꾸면 서버를 다시 띄워야 합니다(실행 중에 다시 읽지 않습니다).

자체 서명 인증서를 만드는 예(OpenSSL을 쓰는 경우. **이 문서는 이 명령을 실행해 확인하지 않았습니다 — 확인 필요: 설치된 OpenSSL
버전의 옵션**):

```text
openssl req -x509 -newkey rsa:2048 -nodes -keyout server.key -out server.pem -days 30 \
  -subj "/CN=vgraph.example" -addext "subjectAltName=DNS:vgraph.example,IP:192.168.0.10"
```

## 3. 토큰 발급·전달·폐기

토큰은 사용자마다 따로 발급합니다. **토큰이 사용자를 정합니다.** `--tokens`를 준 서버는 요청의 `X-Vgraph-User` 헤더를 무시하고,
토큰에 연결된 사용자 이름으로 일합니다(작업 공간 헤더 `X-Vgraph-Workspace`는 그대로 쓰입니다). 각 사용자는 자기 그래프만 목록에서
보고 편집하며, 다른 사용자의 그래프를 편집하려 하면 거부됩니다.

```text
vgraph-mcp token add alice  --root <데이터 폴더>
vgraph-mcp token list       --root <데이터 폴더>
vgraph-mcp token revoke <id> --root <데이터 폴더>
```

| 명령 | 하는 일 |
|---|---|
| `token add <사용자>` | 새 토큰을 발급해 표준 출력에 **한 줄**로 냅니다. **원문은 이때 한 번만 보입니다.** 파일에는 해시만 저장됩니다. |
| `token list` | 토큰 id·사용자·생성 시각·상태를 탭으로 나눠 보입니다. 원문·해시는 보이지 않습니다. |
| `token revoke <id>` | 토큰을 폐기합니다(`token list`에 나온 id). **실행 중인 서버에 곧바로 반영됩니다 — 재시작이 필요 없습니다.** |

- 토큰 파일의 기본 위치는 `<--root>/tokens.jsonl`입니다. 다른 파일을 쓰려면 세 명령 모두 `--tokens <파일>`을 줍니다.
- **서버는 `--tokens <파일>`을 줄 때만 토큰 인증을 켭니다.** 데이터 폴더에 `tokens.jsonl`이 있어도 `--tokens`를 주지 않으면
  인증은 켜지지 않습니다.
- **전달:** 발급 출력은 한 번뿐이므로 그 자리에서 안전한 경로(비밀번호 관리자, 암호화된 메시지 등)로 해당 사용자에게 전하십시오.
  채팅·이메일 평문, 저장소 커밋, 로그에 남기지 마십시오. 분실하면 폐기하고 새로 발급합니다.
- **폐기:** 폐기하면 이미 열려 있던 세션도 다음 요청부터 401로 거절됩니다. 다른 사용자의 토큰은 영향이 없습니다.
- 서버는 토큰 파일이 바뀌었는지 요청마다 (수정 시각, 파일 길이)로 확인해 다시 읽습니다. `token revoke`는 파일 길이가 반드시
  바뀌므로 즉시 반영됩니다. 다만 같은 길이로 손으로 파일을 편집하고 파일시스템의 수정 시각 단위가 거칠면 반영이 늦을 수 있으니
  **파일은 손으로 고치지 말고 `token` 명령으로만 바꾸십시오.**
- 토큰 파일이 사라지거나 깨지면 서버는 **모든 접속을 거부**합니다(복구하면 다시 받습니다). 기동할 때 파일이 없거나 깨져 있으면
  서버가 뜨지 않습니다.
- `token add`와 `token revoke`를 **동시에** 실행하면 한 줄이 유실될 수 있습니다. 한 번에 하나씩 실행하십시오.
- 토큰 값은 서버 출력·오류 메시지·`server.info`·`status`에 나타나지 않습니다.
- 토큰 파일의 접근 권한을 운영체제 쪽에서 따로 제한하십시오(유닉스 `0600` 설정은 시험하지 않았습니다).

## 4. 서버 띄우기 (`serve` 예시)

같은 PC 밖에서 접속하게 여는 기본 예시(주소는 예시입니다):

```text
vgraph-mcp token add alice --root ./vgraph-data
vgraph-mcp serve --root ./vgraph-data \
  --listen 192.168.0.10:7437 \
  --tls-cert server.pem --tls-key server.key \
  --tokens ./vgraph-data/tokens.jsonl
```

- 서버가 준비되면 실제 주소를 `https://…/mcp` 형태로 출력합니다. 클라이언트 설정에는 그 주소를 넣습니다.
- 전체 주소로 열려면 `--listen 0.0.0.0:7437`을 줍니다. 모든 네트워크 어댑터에서 접속이 닿으므로, 가능하면 필요한 어댑터의
  사설 주소 하나만 지정하십시오.
- `--detach`로 콘솔에서 떼어 낼 수 있고, 서버 출력은 `--log-file`(기본 `<데이터 폴더>/server.log`)에 남습니다.
- 끄기·상태 확인은 [server-mode.md](server-mode.md) 1절과 같습니다(`stop`, `status`).

## 5. 리버스 프록시 뒤에 두기

이미 TLS를 처리하는 리버스 프록시(예: nginx)가 있다면, 프록시가 TLS를 끝내고 vgraph 서버에는 **평문**으로 전달하게 할 수 있습니다.
이때 서버에는 `--behind-proxy`를 줍니다.

- vgraph 서버는 **루프백(같은 PC의 프록시) 또는 사설 주소(같은 사설망의 프록시)** 에서만 열 수 있습니다. 공인·전체 주소는 거부합니다.
- `--tokens`는 프록시 모드에서도 필수입니다. 프록시는 `Authorization` 헤더를 지우지 말고 **그대로 전달**해야 합니다.
- TLS 옵션(`--tls-cert`·`--tls-key`)은 프록시가 TLS를 맡을 때는 필요 없습니다.

같은 PC의 프록시 뒤에 두는 예:

```text
vgraph-mcp serve --root ./vgraph-data --listen 127.0.0.1:7437 \
  --behind-proxy --tokens ./vgraph-data/tokens.jsonl
```

같은 사설망의 다른 PC에 프록시가 있는 예(서버는 사설 주소로 열고, 방화벽에서 프록시 PC에서 오는 접속만 허용하십시오):

```text
vgraph-mcp serve --root ./vgraph-data --listen 10.0.0.5:7437 \
  --behind-proxy --tokens ./vgraph-data/tokens.jsonl
```

nginx 설정의 개념 예(**이 문서는 nginx로 실행해 확인하지 않았습니다 — 확인 필요: 사용 중인 nginx 버전에서 아래 설정으로 접속·업로드가 되는지**):

```nginx
server {
    listen 443 ssl;
    server_name vgraph.example;
    ssl_certificate     /path/to/server.pem;
    ssl_certificate_key /path/to/server.key;

    # 나눠 올리기의 chunk 한 번이 최대 16MiB까지 올 수 있어(서버 상한) 기본 1m으로는 413이 납니다.
    client_max_body_size 16m;

    location /mcp {
        proxy_pass http://127.0.0.1:7437/mcp;
        proxy_set_header Host $host;
        # Authorization 헤더는 기본으로 전달됩니다. 지우지 마십시오.
    }
}
```

## 6. 브라우저 앱을 위한 `--allow-origin`

`Origin` 헤더는 **브라우저**가 붙입니다. 에이전트 같은 일반 클라이언트는 보통 보내지 않으며, 보내지 않으면 이 규칙의 영향을 받지
않습니다. 브라우저 앱(웹 페이지)이 서버에 접속해야 할 때만 `--allow-origin <출처>`를 씁니다(여러 번 줄 수 있음).

- **정확히 일치**해야 합니다(스킴·호스트·포트). 와일드카드는 없습니다.
- **브라우저는 기본 포트(`https`의 443, `http`의 80)를 `Origin`에서 생략합니다.** 그러므로 `https://app.example`처럼 **`:443` 없이**
  적습니다. `https://app.example:443`으로 적으면 브라우저가 보내는 `https://app.example`과 달라 403이 납니다.
  기본이 아닌 포트는 `https://app.example:8443`처럼 적습니다.

| 서버 종류 | `Origin`이 있는 요청 | `Origin`이 없는 요청 |
|---|---|---|
| 밖으로 여는 서버 (일반 모드) | 목록에 있는 출처만 통과. 목록에 없거나 **목록이 비어 있으면 403** | 통과 |
| 루프백 서버, 프록시 모드 아님 | 루프백 출처만 통과. **`--allow-origin`은 쓸 수 없음**(기동 거부) | 통과 |
| 루프백 서버 + `--behind-proxy`, **목록 없음** | 루프백 출처만 통과 (지금까지와 같음) | 통과 |
| 사설 주소 + `--behind-proxy` | 밖으로 열린 서버로 판정. 목록에 있는 출처만 통과. 목록이 비어 있으면 **Origin이 있는 요청은 전부 403** | 통과 |
| 루프백 서버 + `--behind-proxy`, **목록 있음** | 목록에 있는 출처만 통과. **루프백 출처도 403** | 통과 |

- 프록시 모드에서 목록을 주면 **같은 PC의 개발용 앱(`http://localhost:3000` 등)도 막힙니다.** 함께 쓰려면 그 출처도 목록에 넣으십시오.
- 프록시 뒤 서버는 브라우저가 보는 **프록시의 공개 출처**(예: `https://app.example`)를 목록에 넣습니다.
- 사설 주소로 연 프록시 모드 서버의 `Origin` 판정은 코드 분기와 기존 시험으로만 확인했고, 실제 네트워크에서는 확인하지 못했습니다(10절).

## 7. 로그인할 때 자동으로 띄우기 (`service install`)

`service install`은 `serve`와 같은 원격 옵션(`--listen`, `--tls-cert`, `--tls-key`, `--tokens`, `--behind-proxy`, `--allow-origin`)을
받습니다.

```text
vgraph-mcp service install --root ./vgraph-data --listen 192.168.0.10:7437 \
  --tls-cert server.pem --tls-key server.key --tokens ./vgraph-data/tokens.jsonl
```

- 원격 바인드 규칙(1절)은 **등록 단계에서 먼저 검사**합니다. 규칙에 어긋나면 등록하지 않습니다.
- 등록 항목에는 **경로만** 들어갑니다. `--root`·`--token-file`·`--tokens`·`--tls-cert`·`--tls-key`·`--log-file`은 **절대 경로로 바뀌어**
  등록되고, 토큰 원문이나 키 내용은 등록하지 않습니다(`--token`은 거부). 따라서 **인증서·키·토큰 파일을 다른 곳으로 옮기면 등록이
  깨집니다.** 옮겼다면 `install`을 다시 하십시오. 실행 파일(`vgraph-mcp`)을 옮겼을 때도 마찬가지입니다.
- 등록 전에 내용만 보려면 `--print <windows|macos|linux>`를 줍니다.
- 자동 시작의 운영체제별 검증 상태는 [server-mode.md](server-mode.md) 2절을 보십시오.

## 8. 방화벽

- 서버가 밖으로 열리는 주소에 처음 바인드하면 Windows가 **방화벽 허용 창**을 띄울 수 있습니다. 허용 범위는 **사설 네트워크만** 고르는 것이
  안전합니다. 공용 네트워크까지 허용하면 카페 같은 곳의 망에도 열립니다.
- 방화벽 규칙은 **고정한 포트**로 만드십시오(포트 `0`은 매번 바뀝니다). 접속을 허용할 원본 주소 범위도 가능한 한 좁히십시오.
- 같은 사설망 안에서도 토큰이 새면 접속할 수 있으니, 방화벽은 토큰을 대신하지 않습니다. 둘 다 쓰십시오.
- **인터넷에 직접 노출하지 마십시오.** 10절 참조.

## 9. MCP 클라이언트 연결 예

서버는 MCP의 HTTP 방식(Streamable HTTP)으로 접속을 받습니다. 클라이언트 설정에 필요한 것은 **서버 주소(`https://…/mcp`)** 와
**`Authorization: Bearer <토큰>` 헤더**입니다.

일반적인 JSON 설정 형태의 예(키 이름은 클라이언트마다 다릅니다):

```json
{
  "mcpServers": {
    "vgraph": {
      "type": "http",
      "url": "https://vgraph.example/mcp",
      "headers": {
        "Authorization": "Bearer <발급받은 토큰>",
        "X-Vgraph-Workspace": "my-agent"
      }
    }
  }
}
```

- `X-Vgraph-User`는 토큰 서버에서 무시되므로 넣을 필요가 없습니다. `X-Vgraph-Workspace`로 작업 공간 이름을 고정하면 재접속해도
  같은 작업 공간을 이어 씁니다([server-mode.md](server-mode.md) 4절).
- **확인 필요:** 특정 MCP 클라이언트(예: 명령줄 도구·편집기 확장)의 설정 키 이름(`type`/`transport`, `headers`의 위치)과 명령줄 등록
  문법은 클라이언트와 버전마다 다릅니다. 해당 클라이언트 문서로 확인한 뒤 적용하십시오. 이 문서는 특정 클라이언트로 실제 접속해 확인한 결과를
  싣지 않았습니다.
- **확인 필요:** 자체 서명 인증서를 클라이언트가 신뢰하게 하는 방법(추가 CA 파일 지정 등)은 클라이언트와 실행 환경마다 다릅니다. 해당
  클라이언트 문서로 확인하십시오.
- 접속이 안 될 때 상태 코드로 원인을 가늠할 수 있습니다: **401** 토큰이 없거나 틀리거나 폐기됨 · **403** `Origin`이 허용 목록에 없음 ·
  **413** 요청 본문이 16MiB 초과 · **503** 세션 수 상한(4096) 초과. TLS 오류는 인증서 주소(SAN)·신뢰 설정을 먼저 보십시오.

## 10. 알려진 한계와 검증 상태

**한계**

- **동시 연결 수에 상한이 없습니다.** TLS 연결을 맺고 요청을 보내지 않은 채 붙잡고 있는 연결도 막지 않습니다(핸드셰이크는 10초 안에 끝나야
  하지만, 그 뒤의 유휴 연결은 제한이 없습니다). 평문 경로도 같습니다. **불특정 다수가 닿는 곳에 노출하기 전에 별도로 검토하십시오.**
- **공개 인터넷 배포 운영은 이 문서의 범위 밖입니다.** 이 절차는 신뢰할 수 있는 사설망(같은 PC·사무실 망)을 전제합니다. 속도 제한, 침입 탐지,
  인증서 자동 갱신 같은 운영 장치는 제공하지 않습니다.
- 세션에는 만료가 없고 최대 4096개입니다(한계 도달 시 새 `initialize`가 503). 나눠 올리기 업로드는 서버 전체에서 동시 8개를 공유하므로,
  한 사용자가 모두 쓰면 다른 사용자는 10분(유휴 만료)이 지나야 새로 시작할 수 있습니다.
- 토큰은 사용자 이름과 연결될 뿐 **권한 단계(읽기 전용 등)는 없습니다.**
- 인증서·키를 바꾸려면 서버를 다시 띄워야 합니다.

**검증 상태**

- 루프백 TLS 접속·개인키 3형식·바인드 거부·`--tokens` 인증·폐기 반영은 자동 시험으로 확인했습니다.
- **이 PC 밖으로 열리는 주소(`0.0.0.0`·사설 IP)에 실제로 바인드하는 확인은 수동 시험 두 개로 분리**되어 있고(`#[ignore]`), 방화벽 창이나
  네트워크 노출을 피하려고 자동으로 돌리지 않습니다:

  ```text
  cargo test -p vgraph-mcp --test serve_remote -- --ignored
  cargo test -p vgraph-mcp --test remote_concurrency -- --ignored --nocapture
  ```

  `remote_concurrency`는 서로 다른 토큰의 클라이언트 5개가 TLS로 동시에 편집·커밋하며 유실과 사용자 혼선을 세어 `SUMMARY` 한 줄로
  출력합니다. 환경 변수 `VGRAPH_REMOTE_LISTEN`(열 주소, 예: `192.168.0.10:0`)·`VGRAPH_REMOTE_RUNS`·`VGRAPH_REMOTE_ROUNDS`로 조정합니다.
  이 시험을 실제 원격 주소에서 돌린 결과는 이 문서에 싣지 않았습니다.
